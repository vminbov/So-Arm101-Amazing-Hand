# A팀 핸드아이 캘리브레이션 (2026-09-30)

SO-101 + AmazingHand 실물에서 뜬 **픽셀 → 관절각** 캘리브레이션입니다.

## 무엇인가

카메라 내부 파라미터도, URDF도, 체커보드도 쓰지 않습니다.
**픽셀 (u,v) → 관절각을 2차 다항식으로 직접 적합**합니다. 그 식 하나가
렌즈 왜곡·카메라 자세·작업대 평면·팔 기구학을 한꺼번에 흡수합니다.

```
관절각 = c0 + c1·u + c2·v + c3·u² + c4·u·v + c5·v²      (u, v 는 /1000)
```

## 파일

| 파일 | 내용 |
|---|---|
| `handeye.json` | 캘리브 결과. 계수·유효범위·오차·오프셋 |
| `handeye_points.csv` | 원본 대응점 30개 (u, v, 관절각 5개) |
| `hardware_spec.json` | 시뮬이 맞춰야 할 실물 기준값 (아래) |

## 성능 (실측)

| 항목 | 값 |
|---|---|
| 수집 | 30점 → 이상치 8점 제외 → **22점** |
| LOO 오차 | **1.23도** (관절별 0.77 ~ 1.54) |
| 손끝 오차 — 쓴 점 | 평균 5.7mm, 최대 16.7mm |
| 손끝 오차 — 안 본 자리 | 평균 **12mm**, 90% 22.8mm |
| 유효 픽셀 범위 | u 351~877, v 256~558 |
| 실제 작업 범위 | **20.9 × 11.4 cm** |
| 축척 | 1px = 0.37mm |
| 작업대 표면 | 팔 기준 z ≈ **−15mm** |

이상치 8점은 **전부 같은 가로줄(v 340~360)** 에 있었고 잔차 부호도 같았습니다.
그 줄만 다른 높이로 찍힌 것이라 자동으로 제외했습니다. 무작위 잡음이 아니라
계통 오차였습니다.

## 각도 기준 — 중요

**`angle_frame: "ours"` = LeRobot 캘리브레이션 기준**입니다.
그쪽(`home_steps=2048` 기본값) 과 다릅니다.

`HANDOFF.md` 에 "우리 실측과 비교하면 `lift`·`wrist_flex` 가 약 100도
어긋난다" 고 적어 두신 것이 이 차이일 가능성이 큽니다. `wrist_roll` 만
1~2도로 일치한다는 것도 그 방향을 가리킵니다 — **부호나 영점이 다른 관절만
어긋나는 모양**입니다.

대조하실 때 쓰실 값:

- 이 캘리브로 만든 자세는 **전부 우리 소프트 리밋과 작업 영역을 통과**합니다
  (`grasp_offline_check` 로 C팀 사진 103장 검증: 리밋 밖 0%, 작업영역 밖 0%)
- 같은 픽셀에서 양쪽 각도를 뽑아 **관절별 차이의 부호와 크기**를 보시면
  변환식(a·x + b)이 바로 나올 겁니다

## 알아둘 것

**`marker_offset_px`** — 캘리브는 손등 **마커(스티커)** 를 목표 픽셀에 갖다
놓습니다. 실제 파지점은 거기서 (+86, +38)px = 약 34mm 떨어져 있어, 그만큼
목표를 옮겨서 보냅니다.

**`grip_trim_px`** — 물체가 손 안에서 놓일 자리 보정. AmazingHand 는 엄지가
좌우로 못 움직여서, 물체가 엄지 쪽으로 조금 치우쳐야 세 손가락이 가둡니다.
가운데면 빠져나갑니다.

**띄우기 25mm** — 캘리브를 뜰 때 손가락이 바닥에 닿아 있었습니다. 그 각도로
그대로 가면 책상을 누릅니다. 역기구학으로 z만 올려서 보냅니다.

**경로는 3단계로** — 관절을 직선 보간하면 **가는 도중에** 손이 누운 채
책상을 훑습니다. 실제로 그렇게 돼서 부하 580으로 멈췄습니다. 도착 자세만
검사해서는 못 잡습니다. 들어올리기 → 목표 위로 → 내려가기로 갑니다.

## 파지 위치에 대한 발견

C팀 캔 사진 23장으로 쟀습니다. **사람 라벨이 예외 없이 물체 중심**에
있습니다 (긴 축 위치의 표준편차 0.00). 그런데 모델은 품질 맵의 최댓값 한
점을 고르느라 중심에서 흔들립니다.

| | 정답까지 평균 | 최악 | 캔 지름 절반(28mm) 초과 |
|---|---|---|---|
| 모델 예측 좌표 | **23mm** | 40mm | **35%** |
| 물체 중심 | **0mm** | 0mm | **0%** |

캔 지름이 57mm이므로 23mm는 손가락이 빗나가 놓치는 크기입니다.
**위치는 물체 중심을 쓰고 각도만 모델에서 가져오면** 해결됩니다.
각도는 모델이 잘 맞히니까요.

단, **대칭 물체에만 맞는 이야기**입니다. 손잡이 달린 컵처럼 비대칭이면
중심이 답이 아닙니다.

## hardware_spec.json

시뮬레이션이 맞춰야 할 실물 기준값입니다. 시뮬 결과가 이 범위를 벗어난
자세를 쓰면 실물로 옮겨지지 않습니다.

| 대조 | 뜻 |
|---|---|
| 시뮬 joint range > 실측 리밋 | 실물에 없는 자세를 쓰는 중 |
| 시뮬이 손목을 실측보다 많이 돌림 | 그 파지는 실물로 안 옮겨짐 |
| 시뮬 성공률 ≫ 실물 성공률 | 시뮬이 뭔가 쉽게 만들어 놓음 |
| 시뮬이 엄지를 많이 굽힘 | 실물은 +5.8도뿐 (일부러 제한) |
| 시뮬이 약지를 씀 | 실물은 파손돼 세 손가락뿐 |

**`wrist_roll` 은 서보 고장이 아니라 기구 간섭입니다.** AmazingHand
결합부가 SO-101 돌출부에 걸립니다. 부품을 갈아도 안 풀리고 **어댑터를 다시
만들어야** 합니다. 이것 때문에 손등이 늘 위로 고정돼 **서 있는 캔처럼 옆에서
감싸야 하는 파지가 불가능합니다.**

시뮬에서 서 있는 캔을 계속 하시려면, 손목을 자유롭게 두는 대신 **"어댑터를
고치면 이만큼 돈다"를 가정으로 명시**하고 그 범위로 제한하시는 게 맞습니다.
그래야 결론이 실행 가능한 제안이 됩니다.
